# Galgame 资源通用开箱流程

一页纸。目标：从资源站下到任何形态的包，都能自己判断、自己拆开、自己跑起来。

---

## 一、先认清一件事：`.enc` 不是压缩包

资源站为了规避网盘审查，会把**已经打好的压缩包再套一层加密**。
所以你在网盘里看到的是 `PC.001.enc` / `PC.002.enc`，类型显示"ENC 文件"。

这层的特征是文件头前 5 个字节是 ASCII 的 `SSEFE`：

```
53 53 45 46 45   <- "SSEFE"
```

这是 **Paranoia S.S.E. File Encryptor** 的容器格式，不是 RAR / 7z / zip。
**用 WinRAR、7-Zip、Bandizip 双击它，永远打不开。**

所以完整链路是两层：

```
.enc 分卷  ──(ssefenc 解密 + 站点口令)──▶  7z/rar 分卷  ──(7-Zip 解压)──▶  游戏目录  ──▶  双击 exe
```

漏掉任何一层都不行。口令通常就写在资源帖里，这一类站点惯例是**站点域名**。

---

## 二、判断手上的文件是哪一种（10 秒版）

看文件头前几个字节，或者直接看扩展名：

| 你看到的 | 含义 | 怎么办 |
| --- | --- | --- |
| `xxx.001.enc` `xxx.002.enc` | 加密容器套分卷 | 先 ssefenc 解密 → 得到 `.001/.002` → 7-Zip 解压 |
| `xxx.7z.001` `xxx.7z.002` | 7-Zip 原生分卷 | 只解 `.001`，它自动续读后面的 |
| `xxx.part1.rar` | RAR 分卷 | 只解 part1 |
| `xxx.zip` + `xxx.z01` | ZIP 分卷 | 7-Zip 解 `.zip` |
| `xxx.tar.gz` / `.tgz` / `.tar.xz` / `.tar.zst` | 两层：外层单流压缩 + 里面是 tar | 直接交给工具，会连着剥两层 |
| `data.xp3` | KiriKiri 引擎资源 | **不用解压**，直接跑同目录 exe |
| `UnityPlayer.dll` + `xxx_Data\` | Unity 游戏 | **不用解压**，双击 `xxx.exe` |
| 一堆 `*.bundle` + `catalog.bin` | Unity Addressables | 已经是解压好的，直接玩 |
| 单文件，头是 `MZ` | Windows exe | 直接跑（可能是自解压） |
| 头是 `Rar!` 但扩展名奇怪 | RAR 改了扩展名 | 改名成 `.rar` 再解 |

**最容易犯的错**：把 `.enc` 当压缩包直接右键解压 → 报"压缩包损坏/格式未知" → 以为资源坏了。
其实只是少做了解密这一步。

## 三、手动操作（不用这个工具也能做）

### 1. 解密 `.enc`

```bat
java -jar ssefenc.jar dec --password 站点域名 -o 输出目录 "D:\下载目录\PC.001.enc"
```

要点：

- `-o` 的输出目录**必须事先存在**，否则报 `Output directory not found`。
- 每一卷都要单独解（`PC.001.enc` 解一次，`PC.002.enc` 再解一次）。
- 退出码：`0` 成功 / `3` 口令错 / `6` 文件损坏（要重下这一卷）/ `2` 输出目录写不进去。
- 解密速度约 140 MB/s，2 GB 的卷十几秒。
- 成功时最后一行打印 `Completed: OK`。

出来的是 `PC.001` / `PC.002`，**没有扩展名**，但头是 `37 7A BC AF 27 1C` = 7-Zip。

### 2. 解压分卷

```bat
7z x "输出目录\PC.001" -o"目标目录" -y
```

只点第一卷，7-Zip 会自己去找 `PC.002`。

**注意**：要用 `7z.exe`（配套 `7z.dll`），**不要用 `7zr.exe`**。
`7zr.exe` 是最小化版本，只认 7z 格式；遇到 zip / rar / tar / gz 会直接报
`ERROR: ... Cannot open the file as archive`，看着像文件坏了，其实只是工具不支持。

### 3. 跑起来

进游戏目录，双击体量最大的那个 `.exe`。
Unity 游戏的 exe 通常只有几百 KB，真正的代码在 `xxx_Data\` 里，别被体积骗了。

## 四、用这个工具

### 图形界面

双击 `游戏解压助手.exe`：

1. 把下载好的文件夹（或那个 `.enc` 文件）**拖到窗口上方的大方块里**，也可以点方块弹出选择框
2. 口令填上（加密的 `.enc` 才需要）
3. 点 **「开始开箱」**；跑久了想停就点 **「停止」**
4. 进度条走完，状态行会写「完成 —— 可以点『启动游戏』了」
5. 点 **「启动游戏」** 直接开玩；点 **「打开游戏目录」** 去翻文件

底栏那个勾选框 **「保留解密出的中间文件」**：不勾就只留游戏本体，省一半磁盘
（13 GB 的包能省 2.7 GB）；勾上则保留 `PC.001` / `PC.zip` 这些中间产物，
方便以后重解不用再解一次密。

### 命令行

```bat
galgame-kit-cli.exe -p 口令 "D:\Downloads\Gamex-123456"
galgame-kit-cli.exe --dry-run "D:\Downloads\Gamex-123456"       :: 只看会做什么
galgame-kit-cli.exe -p 口令 --clean "D:\Downloads\Gamex-123456" :: 解完删掉中间文件
galgame-kit-cli.exe --json "D:\Downloads\Gamex-123456"          :: 结构化输出，接脚本用
```

退出码 `0` 成功 / `1` 失败 / `2` 参数错误。

### 它替你做的判断

1. 扫文件头，认出是 SSEFE / 7Z / RAR / ZIP / XP3 / UnityFS / CPK / NEKOPACK / PE ……
2. 按"组"分开处理（`PC.001.enc`+`PC.002.enc` 算一组，`app.7z.001` 算另一组）
3. 是 SSEFE 就自动调 ssefenc 解密，口令错/文件坏会明确报出来（不会假装成功）
4. 解出来的 7z 先做**完整度体检**：读主头里声明的总长度，和手上所有卷加起来的字节数对比
   - 相等 → 卷齐了，开解
   - 少了 → 直接告诉你"缺 X MB，去把那一卷下完"，**不浪费时间去解一个必然失败的包**
5. 解压后识别引擎，直接指出该双击哪个 exe
6. 如果指向的是**已经解压好的游戏目录**，它会说"不用再解包"并给出启动路径（防止重复操作）
7. 顺手检查磁盘剩余空间够不够

### 输出位置

默认在源文件夹旁边建 `_unpack\`：

```
_unpack\
  decrypted\   <- 解密产物（PC.001 / PC.002）
  game\        <- 解压产物（游戏本体）
```

原始 `.enc` 一律不动。

## 五、常见故障对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 7-Zip 报"无法作为压缩包打开" | 还在 `.enc` 层，没解密 | 先跑 ssefenc |
| ssefenc `exit=3` / Invalid password | 口令不对 | 换口令；注意大小写、别带空格；口令常是站点域名 |
| ssefenc `exit=6` | 这一卷下载不完整 | 重下这一卷（网盘断点续传偶尔会坏块） |
| ssefenc `exit=2` + "拒绝访问" | 输出目录写不进去 | 换一个可写目录；或先用工具目录里的 java 而不是系统 java |
| 解压报 "Unexpected end of archive" | 少了最后一卷 | 看工具的"缺 X MB"提示，补齐 |
| `7zr.exe` 报 Cannot open the file as archive，但文件明明没坏 | `7zr` 只认 7z，不认 zip/rar/tar/gz | 改用 `7z.exe`（配套 `7z.dll`） |
| 双击 exe 没反应 | 缺 VC++ 运行库 | 装 `vc_redist.x64.exe` |
| 启动黑屏 / 闪退 | 路径含中文或超长 | 把游戏目录移到短英文路径，如 `D:\Games\xxx` |
| 文件数比预期少 | 路径超过 260 字符 | 确认 `游戏解压助手.exe.config` 还在 exe 旁边（长路径开关） |
| 提示 Steam 相关错误 | 游戏带 `steam_api64.dll` 但不走 Steam | 一般可忽略；看目录里有没有 `steam_appid.txt` 或免 Steam 说明 |
| 界面是日文 | 语言设置 | 标题画面 OPTION → LANGUAGE 切中文；或看 `LocalizeData\` 里有没有 `cn` |
| 报"缺少 7z.exe / java.exe" | 工具被单独拷走了 | 把 exe 和工具放在同一个目录，或设 `GALGAMEKIT_TOOLS` |

## 六、下次遇到新资源的标准动作

1. **先看扩展名和文件头**，确定分几层（`.enc` 一层 + 压缩一层是常态）
2. **找口令**：资源帖正文、文件名、压缩包注释、站点名。这一类站点九成就是域名
3. **跑 `--dry-run`** 确认识别无误，再跑完整流程
4. **确认卷齐**再开始解（工具会替你判断）
5. 解完直接找最大的 exe 双击
6. **存档位置**（三选一，看包里的说明文件最准）：
   - Godot：`C:\Users\<你>\AppData\Roaming\<游戏内部名>\`
   - Unity：`C:\Users\<你>\AppData\LocalLow\<厂商>\<游戏名>\`
   - 其他引擎：游戏目录下 `save\` 或根目录
   - 有些包会自带 `<存档位置>.txt` 和初始 `*.save`

## 七、工具怎么放

工具（`7z.exe` / `7z.dll` / `ssefenc.jar` / `jre\`）要和 `游戏解压助手.exe`
放在**同一个目录**里：

```
galgame-kit\
  游戏解压助手.exe          ← 双击这个
  galgame-kit-cli.exe
  游戏解压助手.exe.config   ← 长路径开关，别丢
  7z.exe
  7z.dll
  ssefenc.jar
  jre\bin\java.exe
```

整个目录可以原样搬到任何盘、任何机器，程序按**自己所在位置**找工具，不用改配置。

工具想放别处也行：设环境变量 `GALGAMEKIT_TOOLS` 指向那个目录。

> **为什么不能把工具丢进游戏目录里"图省事"**：程序启动的每个子进程都会继承
> 父进程的工作目录和权限环境，某些受限环境（沙箱、受控文件夹、部分安全软件策略）下
> 子进程只能写自己所在的那棵树。把工具散到各处会让"能跑"和"报拒绝访问"随机出现。
> 把工具集中在一个目录，问题只可能出在那一处。
